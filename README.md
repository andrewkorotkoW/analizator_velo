# anal_velo

Анализатор велотренировок: пользователь регистрируется, загружает свои
тренировки (CSV, GPX или FIT), система строит динамический график прогресса
(дистанция и средняя скорость по датам), показывает объём текущей недели,
распределение по зонам пульса и даёт текстовые рекомендации на основе
истории тренировок.

## Формат входных данных

Поддерживаются три формата, их можно смешивать в одной загрузке. Тип файла
определяется по расширению (`.csv`, `.gpx`, `.fit`); если расширение другое
или отсутствует, тип угадывается по содержимому — XML-файл с тегом `<gpx>`
считается GPX, файл с сигнатурой `.FIT` на 8–12 байте — FIT, всё остальное
пытается разобраться как CSV.

### CSV

CSV с заголовком и колонками:

| Колонка         | Обязательна | Описание                              |
|-----------------|-------------|----------------------------------------|
| `date`          | да          | дата тренировки, `YYYY-MM-DD`          |
| `distance_km`   | да          | дистанция, км                          |
| `duration_min`  | да          | длительность, мин                      |
| `avg_speed_kmh` | нет         | средняя скорость, км/ч                 |
| `avg_hr`        | нет         | средний пульс, уд/мин                  |

Файл должен быть в кодировке UTF-8. Каждая строка CSV — отдельная
тренировка. Пример — [`tests/fixtures/sample_workouts.csv`](tests/fixtures/sample_workouts.csv).

### GPX и FIT

Один GPX-трек или один FIT-файл — это одна тренировка. Дистанция и
длительность считаются из точек трека (для GPX — по координатам и времени,
паузы дольше 30 секунд не входят в «время в движении»; для FIT — из
session-сообщения, а если его нет, то агрегируется по record-сообщениям).
Дополнительно, если данные есть в файле, извлекаются средний пульс и набор
высоты. Пример GPX — [`tests/fixtures/sample_track.gpx`](tests/fixtures/sample_track.gpx).

### Несколько файлов и ZIP

В одной загрузке можно передать сразу несколько файлов (в любой комбинации
CSV/GPX/FIT) или ZIP-архив с файлами внутри — каждый файл в архиве
разбирается отдельно тем же способом. Если часть файлов не разобралась,
остальные всё равно сохраняются, а по нераспознанным возвращается список
ошибок с именем файла и причиной.

### Дедупликация

Перед сохранением тренировка сравнивается с уже сохранёнными тренировками
пользователя: если находится запись с той же датой и дистанцией в пределах
±1%, новая тренировка считается дублем и не сохраняется. Ответ на загрузку
сообщает, сколько тренировок сохранено, а сколько пропущено как дубли
(`saved` / `duplicates`).

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app
```

Зависимости — `Flask`, `gpxpy` (разбор GPX) и `fitparse` (разбор FIT);
обе библиотеки чистые на Python и не требуют системных пакетов.

Сервер поднимется на `http://localhost:5000/` (Flask в режиме `debug=True`).
Ключ сессии можно задать переменной окружения `ANAL_VELO_SECRET_KEY`
(по умолчанию используется тестовое значение).

## Пользовательский сценарий

1. Открыть `http://localhost:5000/` — без активной сессии откроется
   страница входа.
2. Зарегистрироваться (`/register`): email, пароль (с подтверждением) и
   необязательные поля профиля — имя, возраст, максимальный пульс, вес.
   После регистрации сразу выполняется вход и переход на дашборд. Если на
   этот email раньше уже загружали тренировки без аккаунта, они
   автоматически привязываются к новому пользователю.
3. Либо войти (`/login`) по email и паролю уже существующего аккаунта — при
   входе тоже подтягиваются ранее не привязанные тренировки с этим email.
   Если аккаунта ещё нет, но такие тренировки есть, страница входа
   подсказывает зарегистрироваться с этим же email.
4. На дашборде выбрать один или несколько файлов (CSV, GPX, FIT или ZIP) и
   нажать «Загрузить» — появится сообщение, сколько тренировок сохранено.
5. Дашборд показывает:
   - график прогресса (дистанция и средняя скорость по датам);
   - блок «Неделя» — дистанция, время, число тренировок за текущую неделю
     и изменение к среднему за предыдущие 4 недели;
   - диаграмму распределения тренировок по зонам пульса (Z1–Z5), если у
     тренировок есть данные о пульсе;
   - текстовые рекомендации;
   - таблицу истории тренировок с колонками даты, дистанции, времени,
     скорости, пульса, набора высоты и источника (`csv`/`gpx`/`fit`) —
     каждую свою тренировку можно удалить кнопкой в строке.
6. В «Профиль» (ссылка сверху) можно посмотреть email и изменить
   необязательные имя/возраст/макс. пульс/вес — эти значения влияют на
   расчёт зон пульса и рекомендаций.
7. «Выйти» завершает сессию и возвращает на страницу входа.

## Эндпоинты

Все страницы и API-эндпоинты, кроме `/login` и `/register`, требуют
активной сессии: страницы (`/`, `/profile`) без входа делают редирект на
`/login`, `/api/...`-эндпоинты без входа отвечают `401 {"error": ...}`.

- `GET/POST /register` — форма регистрации: email, пароль, подтверждение
  пароля и необязательные имя/возраст/макс. пульс/вес. При успехе создаёт
  пользователя, привязывает к нему старые тренировки с этим email (если
  были) и авторизует.
- `GET/POST /login` — форма входа по email и паролю. При успехе привязывает
  старые тренировки с этим email (если были) и авторизует. Если аккаунта с
  таким email нет, но есть непривязанные тренировки — подсказка
  зарегистрироваться.
- `GET /logout` — очищает сессию и возвращает на `/login`.
- `GET/POST /profile` — просмотр и редактирование профиля (имя, возраст,
  макс. пульс, вес — все поля необязательны).
- `POST /api/workouts/upload` — принимает одно или несколько полей `file`
  (CSV/GPX/FIT) либо ZIP-архив с такими файлами внутри; парсит, пропускает
  дубли (см. «Дедупликация») и сохраняет тренировки текущего пользователя.
  Отвечает `{"saved": N, "duplicates": N, "errors": [...]}`.
- `GET /api/workouts` — тренировки текущего пользователя, отсортированные
  по дате.
- `DELETE /api/workouts/<id>` — удаляет тренировку текущего пользователя
  (404, если её нет или она принадлежит другому пользователю).
- `GET /api/recommendations` — возвращает
  `{"recommendations": [...], "weekly": {...}, "hr_zones": {...}}`:
  - `recommendations` — 2–4 текстовых пункта (при менее чем 4 тренировках —
    одно сообщение о нехватке данных);
  - `weekly` — объём текущей недели и сравнение со средним за предыдущие
    4 недели;
  - `hr_zones` — число тренировок и суммарная длительность по 5 зонам
    пульса (Z1–Z5), рассчитанным от максимального пульса пользователя.

## Тесты

```bash
pytest
```

Покрытие включает:

- парсер CSV — обязательные/опциональные колонки, некорректные значения,
  кодировка;
- парсер GPX — расчёт дистанции/времени/скорости/набора высоты/пульса,
  обработка пауз и точек без времени/пульса, ошибки на битом файле;
- парсер FIT — session- и record-сообщения, разные источники дистанции
  (поле `distance` или координаты), ошибки при нехватке данных;
- определение типа файла по расширению и по содержимому (сниффинг);
- дедупликацию — точное совпадение, границы допуска ±1%, разные даты,
  нулевая дистанция, изоляция между пользователями;
- правила рекомендаций таблицей случаев — зоны пульса и их границы,
  недельный объём и правило 10%, признаки перетренированности (рост
  пульса при стабильном темпе, отсутствие отдыха 5+ дней подряд), совет
  после долгой паузы (7+ дней), общий тренд;
- аутентификацию — регистрацию, вход/выход, защиту страниц и API-роутов,
  изоляцию тренировок между пользователями;
- миграцию тренировок с email на аккаунт при регистрации/входе, включая
  повторный вход без дублирования миграции;
- API-эндпоинты и рендер страниц дашборда, профиля, логина и регистрации.
