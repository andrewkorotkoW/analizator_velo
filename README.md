# anal_velo

Анализатор велотренировок: пользователь регистрируется, загружает свои
тренировки (CSV, GPX или FIT), система строит динамический график прогресса
(дистанция и средняя скорость по датам), показывает объём текущей недели,
распределение по зонам пульса и даёт текстовые рекомендации на основе
истории тренировок.

## Формат входных данных

Поддерживаются три формата, их можно смешивать в одной загрузке. Тип файла
определяется по расширению (`.csv`, `.gpx`, `.fit`); если расширение другое
или отсутствует, тип угадывается по содержимому — XML-файл с тегом `<gpx>`
считается GPX, файл с сигнатурой `.FIT` на 8–12 байте — FIT, всё остальное
пытается разобраться как CSV.

### CSV

CSV с заголовком и колонками:

| Колонка         | Обязательна | Описание                              |
|-----------------|-------------|----------------------------------------|
| `date`          | да          | дата тренировки, `YYYY-MM-DD`          |
| `distance_km`   | да          | дистанция, км                          |
| `duration_min`  | да          | длительность, мин                      |
| `avg_speed_kmh` | нет         | средняя скорость, км/ч                 |
| `avg_hr`        | нет         | средний пульс, уд/мин                  |

Файл должен быть в кодировке UTF-8. Каждая строка CSV — отдельная
тренировка. Пример — [`tests/fixtures/sample_workouts.csv`](tests/fixtures/sample_workouts.csv).

### GPX и FIT

Один GPX-трек или один FIT-файл — это одна тренировка. Дистанция и
длительность считаются из точек трека (для GPX — по координатам и времени,
паузы дольше 30 секунд не входят в «время в движении»; для FIT — из
session-сообщения, а если его нет, то агрегируется по record-сообщениям).
Дополнительно, если данные есть в файле, извлекаются средний пульс и набор
высоты. Пример GPX — [`tests/fixtures/sample_track.gpx`](tests/fixtures/sample_track.gpx).

### Несколько файлов и ZIP

В одной загрузке можно передать сразу несколько файлов (в любой комбинации
CSV/GPX/FIT) или ZIP-архив с файлами внутри — каждый файл в архиве
разбирается отдельно тем же способом. Если часть файлов не разобралась,
остальные всё равно сохраняются, а по нераспознанным возвращается список
ошибок с именем файла и причиной.

### Дедупликация

Перед сохранением тренировка сравнивается с уже сохранёнными тренировками
пользователя: если находится запись с той же датой и дистанцией в пределах
±1%, новая тренировка считается дублем и не сохраняется. Ответ на загрузку
сообщает, сколько тренировок сохранено, а сколько пропущено как дубли
(`saved` / `duplicates`).

## Тренировка по фото

Альтернативный способ добавить тренировку — без CSV/GPX/FIT, по фото экрана
велокомпьютера (Garmin, Wahoo, Sigma) или скриншоту приложения (Strava,
Komoot, Apple Fitness и т. п.). OCR распознаёт текст на фото, а разбор ищет
в нём пары «значение + единица» (км, км/ч, уд/мин, м набора высоты, время
`чч:мм:сс` или «N мин», дату в ISO/`ДД.ММ.ГГГГ`/словами) — поэтому подходит
любой экран, где эти величины читаются как обычный текст, без привязки к
конкретному приложению.

Ничего не сохраняется без явного подтверждения — процесс в два шага:

1. `POST /api/workouts/photo` (поле `photo`) — сохраняет фото во временное
   хранилище, прогоняет через OCR и разбирает текст на поля. В ответе —
   `photo_url` (превью), распознанные `date`/`distance_km`/`duration_min`/
   `avg_speed_kmh`/`avg_hr`/`elevation_gain_m`, `confidence` (доля
   распознанных полей) и `fragments` (исходные куски текста, из которых
   извлечено каждое значение), плюс `ocr_backend`/`ocr_message`.
2. Экран подтверждения показывает превью фото и форму с предзаполненными,
   но редактируемыми полями. Только после подтверждения
   `POST /api/workouts/photo/confirm` переносит фото во временном
   хранилище в постоянное (`workspace/photos/<user_id>/<token>.jpg`) и
   сохраняет тренировку с `source="photo"` — дата, дистанция и время
   обязательны, дедупликация работает так же, как для остальных
   источников (см. «Дедупликация» выше).

### OCR-бэкенд

Бэкенд определяется автоматически при каждом запросе:

1. **`vision`** — системный OCR macOS (Vision framework через pyobjc),
   основной бэкенд на Mac; распознаёт `ru-RU`+`en-US` в режиме `accurate`.
2. **`tesseract`** — если Vision недоступен (не macOS), но `tesseract`
   найден в `PATH`: используется `pytesseract` (`lang="rus+eng"`).
3. **`none`** — если недоступно ни то, ни другое: OCR не запускается, поля
   формы остаются пустыми, а в ответе приходит `ocr_message` с подсказкой,
   что установить. Значения в этом случае вводятся вручную на том же
   экране подтверждения.

Установка Tesseract (пакет `pytesseract` уже в `requirements.txt`):

- **Linux**: `sudo apt-get install tesseract-ocr tesseract-ocr-rus`
- **Windows**: установщик [UB Mannheim tesseract-ocr](https://github.com/UB-Mannheim/tesseract/wiki),
  затем добавить путь к `tesseract.exe` в `PATH`.

Vision (только macOS) требует системные пакеты pyobjc — в
`requirements.txt` они закомментированы, так как не собираются вне macOS:
`pyobjc-framework-Vision` и `pyobjc-framework-Quartz` (тянет `pyobjc-core`
как зависимость). Чтобы включить: раскомментировать эти строки в
`requirements.txt` (или `pip install pyobjc-framework-Vision
pyobjc-framework-Quartz`) перед установкой остальных зависимостей.

### Ограничения и хранение фото

- Максимальный размер файла — 15 МБ.
- Форматы — JPG, PNG, HEIC (HEIC требует `pillow-heif`, уже в
  `requirements.txt`; без него — понятная ошибка вместо падения).
- Фото автоматически поворачивается по EXIF и уменьшается до 1600 px по
  большей стороне, сохраняется как JPEG.
- До подтверждения фото доступно только автору загрузки по временному
  токену; после подтверждения — переносится в постоянное хранилище
  пользователя.

### Известные ограничения

- Проверка даты в разобранном OCR-тексте не учитывает число дней в
  конкретном месяце (например, 31 февраля пройдёт проверку) — диапазоны
  месяца, дня и года проверяются по отдельности.
- Если на шаге подтверждения тренировка оказывается дублем, фото уже
  перенесено в постоянное хранилище — файл остаётся на диске без записи в
  БД.
- Ошибка OCR-бэкенда (Vision/tesseract) при загрузке фото не
  перехватывается и приводит к `500`, а не к сообщению об ошибке.

## Установка и запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app
```

Зависимости — `Flask`, `gpxpy` (разбор GPX) и `fitparse` (разбор FIT);
обе библиотеки чистые на Python и не требуют системных пакетов.

Сервер поднимется на `http://localhost:5000/` (Flask в режиме `debug=True`).
Ключ сессии можно задать переменной окружения `ANAL_VELO_SECRET_KEY`
(по умолчанию используется тестовое значение).

## Пользовательский сценарий

1. Открыть `http://localhost:5000/` — без активной сессии откроется
   страница входа.
2. Зарегистрироваться (`/register`): email, пароль (с подтверждением) и
   необязательные поля профиля — имя, возраст, максимальный пульс, вес.
   После регистрации сразу выполняется вход и переход на дашборд. Если на
   этот email раньше уже загружали тренировки без аккаунта, они
   автоматически привязываются к новому пользователю.
3. Либо войти (`/login`) по email и паролю уже существующего аккаунта — при
   входе тоже подтягиваются ранее не привязанные тренировки с этим email.
   Если аккаунта ещё нет, но такие тренировки есть, страница входа
   подсказывает зарегистрироваться с этим же email.
4. На дашборде выбрать один или несколько файлов (CSV, GPX, FIT или ZIP) и
   нажать «Загрузить» — появится сообщение, сколько тренировок сохранено.
5. Дашборд показывает:
   - график прогресса (дистанция и средняя скорость по датам);
   - блок «Неделя» — дистанция, время, число тренировок за текущую неделю
     и изменение к среднему за предыдущие 4 недели;
   - диаграмму распределения тренировок по зонам пульса (Z1–Z5), если у
     тренировок есть данные о пульсе;
   - текстовые рекомендации;
   - таблицу истории тренировок с колонками даты, дистанции, времени,
     скорости, пульса, набора высоты и источника (`csv`/`gpx`/`fit`) —
     каждую свою тренировку можно удалить кнопкой в строке.
6. В «Профиль» (ссылка сверху) можно посмотреть email и изменить
   необязательные имя/возраст/макс. пульс/вес — эти значения влияют на
   расчёт зон пульса и рекомендаций.
7. «Выйти» завершает сессию и возвращает на страницу входа.

## Эндпоинты

Все страницы и API-эндпоинты, кроме `/login` и `/register`, требуют
активной сессии: страницы (`/`, `/profile`) без входа делают редирект на
`/login`, `/api/...`-эндпоинты без входа отвечают `401 {"error": ...}`.

- `GET/POST /register` — форма регистрации: email, пароль, подтверждение
  пароля и необязательные имя/возраст/макс. пульс/вес. При успехе создаёт
  пользователя, привязывает к нему старые тренировки с этим email (если
  были) и авторизует.
- `GET/POST /login` — форма входа по email и паролю. При успехе привязывает
  старые тренировки с этим email (если были) и авторизует. Если аккаунта с
  таким email нет, но есть непривязанные тренировки — подсказка
  зарегистрироваться.
- `GET /logout` — очищает сессию и возвращает на `/login`.
- `GET/POST /profile` — просмотр и редактирование профиля (имя, возраст,
  макс. пульс, вес — все поля необязательны).
- `POST /api/workouts/upload` — принимает одно или несколько полей `file`
  (CSV/GPX/FIT) либо ZIP-архив с такими файлами внутри; парсит, пропускает
  дубли (см. «Дедупликация») и сохраняет тренировки текущего пользователя.
  Отвечает `{"saved": N, "duplicates": N, "errors": [...]}`.
- `GET /api/workouts` — тренировки текущего пользователя, отсортированные
  по дате.
- `DELETE /api/workouts/<id>` — удаляет тренировку текущего пользователя
  (404, если её нет или она принадлежит другому пользователю).
- `GET /api/recommendations` — возвращает
  `{"recommendations": [...], "weekly": {...}, "hr_zones": {...}}`:
  - `recommendations` — 2–4 текстовых пункта (при менее чем 4 тренировках —
    одно сообщение о нехватке данных);
  - `weekly` — объём текущей недели и сравнение со средним за предыдущие
    4 недели;
  - `hr_zones` — число тренировок и суммарная длительность по 5 зонам
    пульса (Z1–Z5), рассчитанным от максимального пульса пользователя.
- `POST /api/workouts/photo`, `POST /api/workouts/photo/confirm`,
  `GET /api/photos/tmp/<token>`, `GET /api/photos/<user_id>/<token>.jpg` —
  загрузка и подтверждение тренировки по фото, отдача превью и сохранённых
  фото (см. «Тренировка по фото» выше).
- `GET /api/export.csv`, `GET /api/export.zip` — экспорт тренировок
  текущего пользователя (см. «Экспорт» ниже).

## Экспорт

Доступно только авторизованным пользователям и только для их собственных
тренировок.

- `GET /api/export.csv` — CSV со всеми тренировками пользователя, колонки
  `date, distance_km, duration_min, avg_speed_kmh, avg_hr,
  elevation_gain_m, source`. Первые пять совпадают с форматом, который
  принимается на вход (см. «Формат входных данных»), поэтому файл можно
  загрузить обратно через `/api/workouts/upload` — лишние колонки
  (`elevation_gain_m`, `source`) парсер CSV игнорирует.
- `GET /api/export.zip` — ZIP-архив GPX-треков: по файлу
  `<дата>_<id>.gpx` на каждую тренировку, у которой сохранён трек
  (`gpx_path`); тренировки без трека (CSV, фото) в архив не попадают. Если
  треков нет вообще, архив будет пустым.

## Тесты

```bash
pytest
```

Покрытие включает:

- парсер CSV — обязательные/опциональные колонки, некорректные значения,
  кодировка;
- парсер GPX — расчёт дистанции/времени/скорости/набора высоты/пульса,
  обработка пауз и точек без времени/пульса, ошибки на битом файле;
- парсер FIT — session- и record-сообщения, разные источники дистанции
  (поле `distance` или координаты), ошибки при нехватке данных;
- определение типа файла по расширению и по содержимому (сниффинг);
- дедупликацию — точное совпадение, границы допуска ±1%, разные даты,
  нулевая дистанция, изоляция между пользователями;
- правила рекомендаций таблицей случаев — зоны пульса и их границы,
  недельный объём и правило 10%, признаки перетренированности (рост
  пульса при стабильном темпе, отсутствие отдыха 5+ дней подряд), совет
  после долгой паузы (7+ дней), общий тренд;
- аутентификацию — регистрацию, вход/выход, защиту страниц и API-роутов,
  изоляцию тренировок между пользователями;
- миграцию тренировок с email на аккаунт при регистрации/входе, включая
  повторный вход без дублирования миграции;
- API-эндпоинты и рендер страниц дашборда, профиля, логина и регистрации;
- разбор OCR-текста фото-тренировки (`photo_parse`) — таблицей случаев по
  каждому полю, двусмысленные и нераспознанные значения;
- OCR-бэкенды (`ocr`) — с подменой бэкенда через параметр в тестах, без
  вызова реального Vision/tesseract;
- маршруты фото-тренировки — загрузку, подтверждение, отдачу временных и
  постоянных фото с проверкой владельца;
- экспорт CSV/ZIP — авторизацию, изоляцию между пользователями,
  round-trip CSV через парсер, ZIP только с GPX-треками;
- слои иллюстрации лоадера (`app/static/img/loader/`) — наличие
  `wheel_rear.png`/`wheel_front.png`/`body.png` и прозрачные «дырки» на
  месте колёс в `body.png`.

Отдельно — node-smoke тест компонента лоадера: чистые функции (без браузера)
и построение DOM оверлея (`show()` собирает три `<img>` — тело и оба колеса)
на минимальной заглушке `document`, без jsdom:

```bash
node tests/js/loader_smoke.js
```

## Лоадер: замена иллюстрации велосипедиста

Анимация лоадера (`app/static/js/loader.js`, `app/static/css/loader.css`)
собрана из трёх PNG-слоёв в `app/static/img/loader/`: `body.png` (тело,
рама, руль — с прозрачными дырками на месте колёс) и вращающиеся
`wheel_rear.png`/`wheel_front.png`. Чтобы заменить иллюстрацию:

1. Положите свой PNG 360×360 с прозрачным фоном (велосипедист сбоку, едет
   вправо) в `app/static/img/loader/cyclist.png`.
2. Запустите `.venv/bin/python scripts/split_cyclist.py` — он найдёт оба
   колеса (тёмные круглые кластеры в нижней трети изображения; если
   детекция ненадёжна — использует запасные координаты под исходную
   иллюстрацию) и пересоберёт `wheel_rear.png`, `wheel_front.png`,
   `body.png`. Требует Pillow (уже есть в `requirements.txt`).
3. Если раскладка колёс на новой иллюстрации существенно отличается от
   исходной, поправьте проценты позиционирования `.velo-loader-wheel-rear`/
   `.velo-loader-wheel-front` в `loader.css` под новые координаты (скрипт
   выводит их в консоль).
4. Закоммитьте все три PNG — скрипт запускается один раз при замене
   картинки, а не на каждой сборке.
